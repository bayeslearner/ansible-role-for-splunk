# The lab gets the front door of the owner's other teaching labs

## Context

The lab is used by people other than the person who runs it: a team working from a shared host, or guests given access to a lab on the owner's homelab. Today a published lab offers a web terminal on one port and the Git server on two others, all bound to `127.0.0.1` unless `LAB_BIND_ADDRESS` widens them. Splunk Web on each node is reachable only from inside the lab network.

The owner's requirement, in his words (2026-11-18): "it has zero setup for other people. … they hit a URL and it gives them the lab homepage, they hit the url for terminal, terminal opens, they hit the web url for splunk or gitlab or whatever, those open. Of course this is AFTER they are authed".

## Options considered

- A mesh VPN (Tailscale) subnet router in the lab. Rejected by the owner: "this is not for just me"; every visitor would need an account on the operator's tailnet.
- An SSH bastion with SOCKS and jump hosts. Needs a client-side setup per visitor, so it fails the requirement.
- A new proxy design with path-based routes. Rejected by the owner: "why are you reinventing wheel again? you did it for cribl teaching and for n8n learning".
- Copy the front door the owner's other labs already use.

## Decision

Copy the front door of the owner's n8n learning lab, which is the same as his Cribl lab's:

- one Caddy container that routes by Host name, one site block per service;
- a static homepage linking every part, choosing public or LAN links by the address it was opened from;
- the controller's existing ttyd terminal, reached through Caddy;
- each Splunk node's Splunk Web and the Git server, each at its own name;
- optionally the lab's own `cloudflared`, with one tunnel rule sending every name to `caddy:80`, and a Cloudflare Access application that admits the people the operator names. Visitors only sign in.

Without a tunnel token the same stack serves the LAN through `LAB_BIND_ADDRESS`, which is the shape for a team on a shared host.

## Consequences

- Spec 05 gains requirement R11 and task group 7.
- The tunnel, its names and the Access application live in the operator's Cloudflare account; this repository carries only the container and the token's place in `.secrets/`.
- Splunk Web, the search head cluster's links between members and Gitea must work behind two proxies (Cloudflare, then Caddy); checked under task 7.5.
